## Phase 1 — Capacitor wrapper on the Raspberry Pi
Setup: Pi (Debian 13, arm64, ~1 GB RAM) runs Node/npm/git/gh. It CANNOT build Android, so builds run in GitHub Actions (cloud).
- Extracted the Netlify deploy into ~/kandies-app/www
- capacitor.config.json: {"appId":"com.kandiesapp.app","appName":"Kandies","webDir":"www"}
- npx cap add android → created the android/ folder

### Troubleshooting
1. .gitignore typo: "android?app?build" plus a missing zip rule
   → fixed in nano (Ctrl+K to cut the line, retype, Ctrl+O, Enter, Ctrl+X)
2. Opened "nano .gitigore" (missing n) → it created a blank NEW file
   → exit with Ctrl+X; use Tab completion for filenames
   (This left a stray file ".gitgnore" that was found and removed later, Oct 19)
3. git commit -m 'Fix gitignore" → mismatched quotes → stuck at a ">" prompt
   → Ctrl+C, then retype with matching double quotes
4. Deploy zip still tracked after adding it to .gitignore
   Cause: git add . ran BEFORE the ignore rule existed; .gitignore never untracks files already committed
   Fix: git rm --cached deploy-*.zip → commit → verify with: git ls-files | grep zip (empty = good)
5. Workflow file created in ~ instead of ~/kandies-app, and folder named "workFlows"
   Fix: mv .github kandies-app/ ; mv .github/workFlows .github/workflows
   Lesson: Linux paths are case-sensitive; GitHub only reads .github/workflows
6. Tried to install the Claude desktop .deb (amd64) on the Pi (arm64)
   → architecture mismatch; removed it; use claude.ai in the browser instead

Final .gitignore: node_modules, .gradle, android/build, android/app/build, deploy-*.zip

## Phase 3 — How updates work after store launch (research answer)
- Supabase/backend and data changes: instant, no store review
- Netlify website changes: instant
- App code changes: new build + store review (Google Play: hours–days; Apple: ~1–2 days)
- OTA live-update plugins exist, but Apple restricts them
- Decision: fix known bugs BEFORE the first store submission

## Phase 4 — Running Kandies locally (Oct 19)
Attempt 1: Parrot OS VM → failed (slow HDD, 20 GB disk too small). Full details in pi-labs.
Attempt 2: directly on Windows → worked.

### Troubleshooting
1. "python" not recognized → installed from the Microsoft Store prompt (Python 3.15)
2. cd error "path does not exist" → typo "kandies-app-mmaster" → use Tab completion
3. Paste not working in PowerShell
   Cause: commands copied on my phone; clipboards don't sync between devices
   Fixes: open the chat on the PC; title-bar icon > Edit > Paste; Properties > QuickEdit Mode + Ctrl key shortcuts
4. Firefox error "SSL received a record that exceeded the maximum permissible length"
   Cause: Firefox HTTPS-Only mode forced https://, but python http.server only speaks plain HTTP
   Evidence: garbled "400 Bad request" lines in the server log = TLS handshake bytes hitting an HTTP server
   Fix: use http://localhost:8080 in Chrome
5. Windows Firewall prompt for Python (Public networks pre-ticked)
   → Cancel. localhost never leaves the PC. Least privilege: never allow Public for a dev server
6. "PowerShell not responding" → it was busy running the server (log lines = page requests). Stop it with Ctrl+C, and run other commands in a second window
7. Two commands pasted together on one line, unclosed quote → stuck at a ">>" prompt → Ctrl+C; paste one command at a time
Note: the local copy talks to the LIVE Supabase database. Anything done while testing is real data.

## Phase 5 — Windows dev workflow (Git-linked)
- winget install --id GitHub.cli -e ; winget install --id Git.Git -e (first winget use → accept msstore terms with Y)
- Reopen PowerShell after installs (PATH only refreshes in new windows)
- gh auth login → GitHub.com / HTTPS / Yes / web browser → "Logged in as duppy-c"
  (The same login froze inside the Parrot VM's hardened Firefox; host Chrome worked first try)
- gh repo clone duppy-c/kandies-app → C:\Users\<you>\kandies-app
- git config --global user.name / user.email
- winget install --id VSCodium.VSCodium -e → File > Open Folder → Trust (turns off Restricted Mode)

Daily loop:
  1. Edit www\index.html in VSCodium, save with Ctrl+S
  2. Window 1: cd ~\kandies-app\www ; python -m http.server 8080 → http://localhost:8080 (Ctrl+Shift+R)
  3. Window 2: cd ~\kandies-app ; git add -A ; git commit -m "..." ; git push
  4. The push triggers an automatic Android test build (Actions tab)
- Pi copy: run git pull before working there again
- Delete the old unlinked Downloads\kandies-app-master copy

### Troubleshooting — duplicate .gitignore
Problem: VSCodium showed two ".gitignore" files with different icons
Diagnosis: diamond icon = the real file (all 5 rules); plain icon = only "deploy-*.zip". The icon difference meant the editor didn't recognize the second file as a gitignore
Root cause: the commit output showed its true name, ".gitgnore" (from the Phase 1 nano typo)
Fix: deleted it → commit 7099f9a "Remove duplicate gitignore" → pushed → Android build passed (green check)
Lesson: when names look identical, compare icons and contents; git output shows exact filenames
