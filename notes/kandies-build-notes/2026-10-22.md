## Database changes (all applied to live, all verified)

**Artist account flow**
- `become_artist(p_name)`: the only way a listener becomes an artist. One-way.
- `guard_artist_insert` trigger: artist rows can only be created by the official switch, admins, or server jobs.
- `artist_claim_emails` table (admin-only) + `my_claimable_profile()` + `claim_my_profile()`: a verified email matching an unclaimed profile can claim it once. The email is deleted after the claim.

**Artist field lock**
- `protect_artist_columns` trigger on `artists`: an artist editing their own row can't change owner, claim code, claimed date, id or created date. The rights-agreement date can be set once and never changed. The Ohio tag can be turned on by the artist but only removed by staff. Admins and server jobs are not limited.

**Signup**
- `handle_new_user()` rewritten: account type only accepts `listener` or `artist` (anything else becomes listener). New artists start as "New Artist" instead of part of their email.

**Comments**
- `clean_new_comment` trigger on `artist_comments`: the author name is always set by the database (artist name, then profile name, then "Listener"). Body is trimmed, can't be empty, 500 characters max. Time is set by the server.
- `comment_reports` table: users can file a report (spam, harassment, hate, sexual, other) but can't read reports or report as someone else. Admins read and clear. Deleting a comment removes its reports.
- `user_blocks` table: each user manages only their own blocks.
- `check_display_name` trigger + unique index on profile names: 2–30 characters, safe characters only, reserved words blocked, can't copy an artist's name or another user's name. (In place for when listeners get profile names.)

## Troubleshooting

| Problem | Cause | Fix |
|---|---|---|
| Copy-Item "path not found" | Commands ran before the download finished | Delete → download → check size → copy, one step at a time |
| Get-ChildItem found nothing | Filter typed as `"index"` (no `*`), or a stray `\` at the end | Use `-Filter "index*"` |
| Old file size showed up | The old download was still in Downloads | `Remove-Item` the old file first, then download |
| "Potential issue detected" pop-up in SQL Editor | Supabase warns on any `drop` | Expected for `drop trigger if exists`; click Run query |
| Claim Test had no comment section | Artist pages aren't public until they have songs | Tested comments on a live artist page instead |
| Report insert with a read-back failed (practice copy) | Users may file reports but not read them | App inserts without reading back |
| Supabase status banner | Supabase API gateway incident (their side) | SQL Editor still worked; held app tests until stable |

## Lessons

- Test every hole as an ordinary user first, then fix, then run the same test again. "Success" isn't proof; a before/after result is.
- Never trust names, types or limits sent by the app. The database should set or check them.
- Anything the public can read (like artist names) must not be built from private data (like email).
- Run PowerShell steps one at a time and check the file size before copying.
