## Changes

**Site (Netlify):**
- New `www/_headers`:
  - `X-Frame-Options: DENY`
  - `X-Content-Type-Options: nosniff`
  - `Referrer-Policy: strict-origin-when-cross-origin`
  - `Permissions-Policy: camera=(), microphone=(), geolocation=(), payment=()`
- Content-Security-Policy deliberately left for later (single-file app; needs careful testing).

**Android release:**
- Java 21 (Temurin) installed on the Windows PC.
- Upload key `kandies-upload.jks` (RSA 2048, alias `kandies-upload`) in a private folder outside the project.
- Backup on USB drive, verified to open with the same fingerprint. Password stored separately.
- GitHub secrets `ANDROID_KEYSTORE_BASE64` and `ANDROID_KEYSTORE_PASSWORD` set via the GitHub CLI (key piped from the file, password typed at a prompt; never on the clipboard or in a command).
- New workflow `.github/workflows/android-release.yml` (manual run only): builds, signs the .aab, prints the signing fingerprint, deletes the key from the build machine, uploads the .aab (kept 7 days).
- Signed bundle downloaded to `C:\Users\<you>\kandies-release\app-release.aab` (outside the repo).

## Lessons

- Give exact file locations as commands; Save As dialogs remember the last folder.
- Check `git status` before every commit so test files never get published.
- Always label which device and terminal a command runs on.
- Keep signing keys outside the repo, back them up in two places, and store the password separately.
- Verify a signed build by matching its fingerprint to the key, not just by a green check.
