# Kandies Build Notes — Oct 19, 2026

## Running Kandies locally on Windows
- Problem 1: "python" not recognized → installed via Microsoft Store prompt (Python 3.15).
- Problem 2: cd failed "path does not exist" → typo "kandies-app-mmaster". Fix: use Tab completion for folder names.
- Problem 3: Firefox showed "SSL received a record that exceeded the maximum permissible length."
  - Cause: Firefox HTTPS-Only mode upgraded to https://, but Python's http.server only speaks plain HTTP. Server logs showed garbled "400 Bad request" lines = TLS handshake bytes sent to an HTTP server.
  - Fix: open http://localhost:8080 in Chrome.
- Problem 4: Windows Firewall prompt for Python (Public networks pre-ticked).
  - Fix: Cancel. localhost traffic never leaves the PC, so no firewall rule is needed. Least privilege: never allow Public networks for a dev server.
- Command: `python -m http.server 8080` (run inside the www folder)

## Paste not working in PowerShell
- Problem: Right-click/Ctrl+V pasted nothing.
- Cause: Commands were copied on phone; the PC clipboard was empty. Clipboards don't sync between devices.
- Fixes: Open the chat on the PC browser; or use Edit > Paste from the PowerShell title-bar icon; Properties > Options > QuickEdit Mode + Ctrl key shortcuts.

## Git workflow set up on Windows
- `winget install --id GitHub.cli -e` and `winget install --id Git.Git -e` (first winget use asks to accept msstore terms → Y)
- Close and reopen PowerShell after installs (PATH only refreshes in new windows)
- `gh auth login` → GitHub.com / HTTPS / Yes / web browser device code → "Logged in as duppy-c"
- `gh repo clone duppy-c/kandies-app` → C:\Users\<you>\kandies-app
- `git config --global user.name` / `user.email`
- `winget install --id VSCodium.VSCodium -e`; opened the folder and trusted it (Restricted Mode off)
- Note: the earlier device-code login froze inside the Parrot VM's hardened Firefox; on host Chrome it worked first try.

## Duplicate .gitignore
- Problem: VSCodium showed two ".gitignore" files with different icons.
- Troubleshooting: Opened both. The diamond icon had all 5 ignore rules; the plain icon held only "deploy-*.zip". The icon difference meant the editor didn't recognize the second file as a gitignore.
- Cause: The commit output revealed its real name, ".gitgnore" (missing "i"), a typo from an earlier command on the Pi. Git never used it.
- Fix: Deleted it, then `git add -A` → `git commit -m "Remove duplicate gitignore"` → `git push` (commit 7099f9a). The push triggered a GitHub Actions Android build.
- Lesson: When filenames look identical, compare icons and contents; command output (delete mode ... .gitgnore) shows the true name.
